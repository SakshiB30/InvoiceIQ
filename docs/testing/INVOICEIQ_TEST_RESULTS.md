## Counts for executed checks

- Completed executable checks: 16
- PASS: 14 (frontend build, backend suite, auth smoke/registration/login/profile checks, invoice-create regression, two-user isolation, scoped analytics, upload rejection and invoice state checks)
- FAIL: 2 (frontend lint and the reverted exploratory JWT test compilation)

The count above treats each results-table row marked PASS or FAIL as one check; NOT RUN and NEEDS REVIEW rows are separate. The backend suite ran two JUnit test cases per successful run; both passed. The earlier backend attempt that failed because `GEMINI_API_KEY` was unset was recovered by the isolated rerun above and is not counted as a separate test case. The exploratory test compilation failure was caused by the temporary test addition and was reverted; it is included transparently in the check count but is not a failing test in the final repository state. Test users and invoice records were written only to the two named audit databases; the configured `invoiceiq` database was untouched. Do not interpret these counts as coverage of the full QA matrix.
